## Summary

**cartograpy** is an open-source Python package that streamlines the entire geospatial data workflow—from data acquisition to preprocessing to cartographic visualization—through a simple and intuitive API. Its design enables both beginners and experts to visualize, analyze, and showcase spatial data with just a few lines of code. Built on established libraries like Cartopy, GeoPandas, OSMnx, Rasterio, and Matplotlib, cartograpy provides a *single* cohesive interface for tasks that previously required multiple tools — from fetching administrative boundaries, OpenStreetMap features, elevation models, climate time series, or Google Earth Engine imagery, to producing static, bivariate, hexbin, or interactive web maps. By unifying data retrieval, preparation, and mapping in one package, cartograpy lowers the barrier to entry for geographic data analysis and promotes efficient, reproducible research.

The package’s core philosophy is to make “mapping in Python the way it was always meant to be,” emphasizing clarity and ease-of-use. It introduces a clear modular structure (data acquisition, processing, and mapping) that mirrors the typical stages of geospatial analysis, thereby helping users logically organize their workflows. Geospatial analysts, environmental scientists, urban planners, and other researchers can use cartograpy to quickly obtain geographic datasets, perform transformations or analyses on them, and create publication-quality static maps without needing to switch contexts or master multiple libraries.

## Statement of Need

Geospatial data analysis often involves a fragmented ecosystem of tools. Analysts frequently rely on desktop GIS software (such as QGIS or ArcGIS) or a combination of Python libraries to accomplish different steps of a project. Traditional GIS software provides extensive functionality but can be cumbersome for automation and reproducibility, besides requiring manual effort for data preparation and map design. On the other hand, Python libraries like GeoPandas for data manipulation or Cartopy/Matplotlib for mapping address specific parts of the workflow, but integrating them for end-to-end analysis demands substantial expertise. In particular, gathering data (e.g., downloading boundaries or OpenStreetMap features) often requires separate tools or APIs (such as OSMnx for OSM data, or custom scripts for geocoding and fetching datasets). This complexity can hinder newcomers and slow down experienced users.

**cartograpy** was created to fill this gap by offering a **unified, all-in-one toolkit** for geospatial analysis in Python. It addresses the need for a single library that **simplifies common tasks** (data acquisition, cleaning, analysis, and visualization) while remaining flexible for advanced use. By wrapping and integrating functionality from key libraries and data services, cartograpy enables users to accomplish in one package what previously required several. This integration not only saves time but also reduces the learning curve and potential compatibility issues between disparate tools. In research contexts, cartograpy facilitates reproducible workflows: a complete geospatial analysis (from data retrieval to map output) can be captured in a concise Python script or Jupyter notebook, aiding transparency and repeatability.

Furthermore, cartograpy’s focus on clear modular organization around the stages of analysis (data, processing, mapping) provides conceptual clarity. This design encourages good practices by separating concerns (e.g., obtaining data vs. transforming it vs. visualizing results), yet the modules work seamlessly together. No equivalent open-source Python package currently offers this level of integration with such simplicity. Other solutions either address only parts of the pipeline or require significant boilerplate code to connect steps. By building on open data sources and libraries, cartograpy democratizes access to geospatial analysis, offering a free and open alternative to proprietary GIS software (in contrast to ArcGIS, which is closed-source and costly). In summary, cartograpy’s development is motivated by the growing demand for efficient, easy-to-use geospatial tools in research and data science, bridging the gap between powerful GIS capabilities and Python’s data science ecosystem.

## Functionality

**cartograpy** provides a broad range of functionality organized into four main areas: data acquisition, data processing, mapping, and project organization. Below we highlight key features in each category:

- **Geographic Data Acquisition:** The package offers convenient one-line commands to fetch a variety of common geospatial datasets. For example, users can download:
  - **Administrative Boundaries:** Country, regional, or municipal boundary polygons from the global **geoBoundaries** database, by simply specifying a country name and administrative level.
  - **Continental Outlines:** Vector boundaries for continents or sub-continents.
  - **Hydrographic Networks:** River and waterway layers at continental scale (via the `Hydro` module).
  - **OpenStreetMap Features:** Points of interest and infrastructure (schools, buildings, roads, hospitals, etc.) via the `OSM` class, leveraging OpenStreetMap’s rich data.
  - **Geocoding Services:** Forward and reverse geocoding of place names or addresses to coordinates (through the `Geocoder` class).
  - **World Bank Indicators:** Development indicators (e.g., population, GDP, etc.) from the World Bank’s API, fetched and joined with country geometries via the `WorldBank` class.
  - **Elevation Models:** SRTM digital elevation data for a region of interest, via the `DEM` class.
  - **Climate and Weather Series:** Time series of climate/weather variables from NASA POWER, via the `Climate` class.
  - **Satellite Imagery:** Access to Google Earth Engine collections and composites via the `Gee` class, for users with an Earth Engine account.
  
  All retrieved data are automatically formatted as pandas DataFrames or GeoDataFrames for easy manipulation. Notably, cartograpy handles the online data fetching internally (using APIs or web services), so users can obtain ready-to-use geospatial datasets with minimal effort, as long as an internet connection is available. For several of these connectors (e.g., `Climate`, `DEM`, `GeoBoundaries`), repeated requests to the underlying web services are cached on disk (via `requests-cache`) to speed up iterative work and reduce load on the providers.

- **Data Preprocessing and Processing:** The **processing** module provides tools to transform and analyze geospatial datasets. It can **import** virtually any common geospatial file format (vector or raster), such as Shapefile, GeoJSON, KML, GPX, GeoPackage, CSV, Parquet, and more. Likewise, it can **export** data to various formats for use in GIS software or web applications (e.g., saving to Shapefile, GeoJSON, etc.). Additional processing capabilities include:
  - **Automatic dataset listing:** Discover all geospatial files in a directory at a glance.
  - **Format conversion:** Convert datasets between different file formats by loading with `load()` and writing with `save()`.
  - **Geospatial operations:** Compute geometry centroids, perform spatial joins and attribute joins between layers, merge multiple GeoDataFrames, clip data to a region of interest (by extent or a masking polygon), and more. For example, one can quickly calculate the centroids of polygons or join a shapefile of regions with a table of statistical data by region ID.
  - **Attribute creation:** Add new attributes or columns to data based on expressions or functions applied to existing data (useful for deriving metrics or categories on the fly).
  - **DataFrame/GeoDataFrame integration:** The processing functions work directly with pandas DataFrames and GeoPandas GeoDataFrames, allowing users to blend cartograpy’s tools with the rich pandas data manipulation ecosystem.

- **Cartographic Mapping and Visualization:** The **mapper** module enables fast creation of static and interactive maps for visualization of geospatial data. At the center is a powerful `Map` class that wraps Matplotlib and Cartopy functionality to simplify map generation. Key features include:
  - **Layer addition:** Easily add multiple layers to a map, such as choropleth polygons, point markers, line vectors (e.g., road or river networks), or raster tiles/images. The Map class handles coordinate reference systems and plot extents under the hood, so different data sources can be combined seamlessly.
  - **Styling elements:** Add common map decorations and annotations with one-liners. For instance, users can add a north arrow, scale bar, graticule (latitude/longitude grid lines), labels for features, titles and subtitles, and custom color palettes or shading. cartograpy includes a variety of preset color palettes (including those from Seaborn and Matplotlib), Google Fonts integration for map typography, and allows custom palettes.
  - **Legend management:** Generate and place legends automatically, with several built-in style options (e.g., scientific, minimalist, academic styles) to suit different presentation needs. Legends can be customized or omitted as needed.
  - **Specialized map types:** Beyond the standard choropleth, cartograpy supports bivariate choropleth maps (`plot_bivariate_choropleth`) for jointly visualizing two variables, hexagonal-binning maps (`make_hex_grid`, `plot_hexgrid_choropleth`) for aggregating point density, situation/inset maps (`SituationMap`) that place a study area within a wider context, and simple interactive web maps (`WebMap`) exported as standalone HTML.
  - **Figure sizing and export:** Choose standard paper sizes (A4, A3, etc.) or custom dimensions for the figure. The package can automatically adjust the map’s extent and aspect to optimally fit the data (“smart centering”) so that the layout is well-balanced on the chosen canvas. Completed maps can be rendered to high-quality image formats like PNG and SVG for use in publications or reports.
  
  Through these features, cartograpy drastically reduces the amount of code needed to produce a polished map. For example, a user can create a choropleth map of regional data with a title, north arrow, scale, and legend in just a few lines, whereas doing the same manually with Matplotlib and Cartopy would be considerably more involved. By automating many cartographic decisions (while still allowing manual overrides), cartograpy helps users focus on the analytical content of the map rather than low-level plotting details.

- **Project Organization:** The **`Project`** class helps structure the folders and outputs of a mapping project, keeping track of the coordinate reference system used across datasets and validating the integrity of files it manages (e.g., detecting missing shapefile sidecar files). This is a lightweight, opt-in convenience layered on top of the other modules rather than a requirement for using them.

## Implementation and Architecture

cartograpy is implemented in Python and is designed as a lightweight wrapper around robust existing libraries. The project is open-source (MIT licensed) and currently at version 2.0.3. Internally, the package is organized into five primary modules that correspond to the stages of geospatial work: **`cartograpy.data`**, **`cartograpy.processing`**, **`cartograpy.mapper`**, **`cartograpy.styling`**, and **`cartograpy.project`**. This modular architecture promotes clarity: for instance, `data` contains classes for acquiring external datasets, `processing` offers data manipulation functions, `mapper` contains the Map class and plotting functions, `styling` provides helpers for customizing map appearance (fonts, colors, etc.), and `project` helps organize a project's folders, outputs, and CRS bookkeeping.

Under the hood, cartograpy leverages a range of established geospatial and scientific libraries. Key dependencies include **GeoPandas** (for data structures and file I/O), **Shapely** and **PyProj** (for geometric operations and coordinate reference systems), **Rasterio** and **Fiona** (for raster and vector I/O), **OSMnx** (for querying OpenStreetMap data), **geopy** (for geocoding services), **wbdata** (for World Bank indicators), **geemap** (for Google Earth Engine access), and **Cartopy** (for cartographic projections and integration with Matplotlib). Visualization is built on **Matplotlib** (with the aid of Cartopy for map projections and **matplotlib-map-utils**/**drawarrow** for scale bars and north arrows), and additional packages like **Seaborn**, **pypalettes**, **pyfonts**, **SciencePlots**, **mplcyberpunk**, and **geohexgrid** are used to enrich the styling and hexbin-mapping options. For several data connectors, network requests to remote services are cached on disk via **requests-cache**. By standing on the shoulders of these libraries, cartograpy can provide reliable performance and accuracy — for example, it relies on Cartopy’s projection engine to ensure that map layers are correctly projected and on GeoPandas for reading/writing a wide variety of GIS file formats.

Each data acquisition class in `cartograpy.data` encapsulates a specific source or service (e.g., the `GeoBoundaries` class fetches boundary shapefiles from the geoBoundaries API, the `OSM` class uses OSMnx/Overpass API to retrieve OSM features, and `WorldBank` uses the World Bank’s REST API via the `wbdata` library). This design abstracts away the details of interacting with each service — the user calls a method like `Bound().get_admin("France", adm=1)` and receives a GeoDataFrame of French regions, without needing to manually download or unzip any files. Similarly, processing functions in `cartograpy.processing` call underlying GeoPandas or Shapely functions, ensuring that heavy computations are done using optimized code. The `cartograpy.mapper.Map` class wraps Matplotlib’s Figure and Axes objects along with Cartopy’s GeoAxes, handling the creation of a map axis with a specified projection behind the scenes (WGS84 geographic coordinates are assumed by default for simplicity, but users can specify projections if needed).

The architecture emphasizes **extensibility** and **maintainability**. Since cartograpy primarily glues together existing tools, it remains relatively thin: its role is to provide a smoother user interface rather than re-implement complex geospatial algorithms. This means the codebase is easier to maintain, and updates to underlying libraries (e.g., a new release of GeoPandas or Cartopy) can be incorporated by adjusting cartograpy’s wrappers if necessary. The modular approach also means users can use only what they need (for example, one could use just the data module to fetch data and then do custom analysis, or use the mapping module with their own preprocessed GeoDataFrame). This flexibility makes cartograpy applicable to a variety of workflows.

## Quality Control

Quality assurance has been considered in the development of cartograpy, though as an emerging project (development status “Alpha”) there is ongoing work to further harden the software. The source repository includes an automated test suite (using **pytest**) with several hundred tests covering the data, processing, mapper, styling, and project modules, to verify core functionality and prevent regressions. Continuous integration is set up via GitHub Actions, running a linting pass (**flake8**) followed by the full test suite across three operating systems (Ubuntu, macOS, Windows) and three Python versions (3.11–3.13) on every push and pull request, ensuring that the package installs correctly and behaves consistently across environments. In addition, the project follows standard code style practices with **black** for formatting and **mypy** for static type checking during development. These tools help maintain code quality and readability as the codebase grows.

The documentation for cartograpy is comprehensive and serves as an important part of quality control. The official documentation site includes quick-start guides, an API reference, and numerous usage examples (with code snippets and output maps). These examples double as integration tests — by executing them, the developers ensure that all features work together as intended. The documentation also helps users avoid misuse by clearly explaining each function’s purpose and parameters. User feedback is facilitated through an issue tracker on GitHub, where bug reports and feature requests can be filed. This open feedback loop allows the author to address problems and incorporate improvements.

So far, cartograpy has demonstrated its ability to produce correct results on common tasks: for instance, boundary data fetched through `cartograpy.data.GeoBoundaries` have been cross-validated against known sources (like the geoBoundaries dataset publication), and maps generated by the `Map` class have been visually inspected for accuracy of feature placement and styling. As the project matures, additional unit tests and possibly continuous deployment of documentation (to ensure examples remain up-to-date) will be added. Overall, while still young, cartograpy adheres to modern software development best practices to ensure reliability and usability for the community.

## Use Cases

cartograpy’s unified approach lends itself to a variety of use cases across research and applied domains. A few representative scenarios include:

- **Socio-Economic Data Mapping:** A researcher can quickly fetch country or regional boundaries and join them with statistical data (e.g., population or economic indicators) to create choropleth maps. For example, using the World Bank interface and geoBoundaries, one could retrieve the latest population data for all countries and visualize it on a world map with just a handful of commands, producing a ready-to-publish figure of global population distribution.
- **Urban Planning and Infrastructure Analysis:** City planners or geospatial analysts can use cartograpy to obtain OpenStreetMap data such as road networks, public facility locations, or land use polygons for a city, then analyze and plot these on a map. For instance, one might download all hospital locations in a region and the road network via the `OSM` module, then use processing functions to filter and clip these data to the city boundary, and finally map them to assess coverage gaps. The process is streamlined compared to manually combining OSMnx (for data) and separate plotting code.
- **Environmental and Hydrological Studies:** cartograpy can pull continent-scale hydrographic datasets (rivers, lakes) and help focus on a specific area. As an example, an environmental scientist studying water resources in West Africa could download the entire African river network (`Hydro` class), then use a polygon of the target country to clip the river network (`processing.clip_gdf_by_mask`) and visualize the result on an A4 map. The inclusion of automatic scaling, north arrow, and legend allows the scientist to produce a clear map of rivers in the study area with minimal effort.
- **Educational Use and Rapid Prototyping:** For teaching GIS or for quick exploratory data analysis, cartograpy allows students and analysts to perform common geospatial tasks without extensive setup. A class assignment might involve geocoding a list of addresses and mapping them—using cartograpy, students can geocode addresses via the `Geocoder` and plot them on a base map in a straightforward script, focusing on interpretation rather than coding boilerplate. Similarly, data journalists or analysts can prototype maps within a Jupyter notebook interactively, retrieving data and updating map styles on the fly to tell a story with spatial data.

These use cases demonstrate cartograpy’s value in reducing friction in the geospatial workflow. By consolidating capabilities, the package enables quicker iteration and helps ensure that the technical overhead does not impede insights. Each scenario that would typically involve multiple disparate steps or software can be achieved within the cartograpy framework, highlighting its unique contribution to the geospatial toolkit.
