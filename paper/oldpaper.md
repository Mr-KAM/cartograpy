Summary
cartograpy is an open-source Python package that streamlines the entire geospatial data workflow—from data acquisition to preprocessing to cartographic visualization—through a simple and intuitive API. Its design enables both beginners and experts to visualize, analyze, and showcase spatial data with just a few lines of code. Built on established libraries like Cartopy, GeoPandas, OSMnx, Rasterio, and Matplotlib, cartograpy provides a single cohesive interface for tasks that previously required multiple tools. By unifying data retrieval, preparation, and mapping in one package, cartograpy lowers the barrier to entry for geographic data analysis and promotes efficient, reproducible research. The package’s core philosophy is to make “mapping in Python the way it was always meant to be,” emphasizing clarity and ease-of-use. It introduces a clear modular structure (data acquisition, processing, and mapping) that mirrors the typical stages of geospatial analysis, thereby helping users logically organize their workflows. Geospatial analysts, environmental scientists, urban planners, and other researchers can use cartograpy to quickly obtain geographic datasets, perform transformations or analyses on them, and create publication-quality static maps without needing to switch contexts or master multiple libraries.

Functionality
cartograpy provides a broad range of functionality organized into three main areas: data acquisition, data processing, and mapping. Below we highlight key features in each category:
Geographic Data Acquisition: The package offers convenient one-line commands to fetch a variety of common geospatial datasets. For example, users can download:
Administrative Boundaries: Country, regional, or municipal boundary polygons from the global geoBoundaries database, by simply specifying a country name and administrative level.
Continental Outlines: Vector boundaries for continents or sub-continents.
Hydrographic Networks: River and waterway layers at continental scale (via the Hydro module).
OpenStreetMap Features: Points of interest and infrastructure (schools, buildings, roads, hospitals, etc.) via the OSM class, leveraging OpenStreetMap’s rich data.
Geocoding Services: Forward and reverse geocoding of place names or addresses to coordinates (through the Geocoder class).
World Bank Indicators: Development indicators (e.g., population, GDP, etc.) from the World Bank’s API, fetched and joined with country geometries via the WorldBank class.
All retrieved data are automatically formatted as pandas DataFrames or GeoDataFrames for easy manipulation. Notably, cartograpy handles the online data fetching internally (using APIs or web services), so users can obtain ready-to-use geospatial datasets with minimal effort, as long as an internet connection is available.
Data Preprocessing and Processing: The processing module provides tools to transform and analyze geospatial datasets. It can import virtually any common geospatial file format (vector or raster), such as Shapefile, GeoJSON, KML, GPX, GeoPackage, CSV, Parquet, and more. Likewise, it can export data to various formats for use in GIS software or web applications (e.g., saving to Shapefile, GeoJSON, etc.). Additional processing capabilities include:
Automatic dataset listing: Discover all geospatial files in a directory at a glance.
Format conversion: Convert datasets between different file formats with a single function call.
Geospatial operations: Compute geometry centroids, perform spatial joins and attribute joins between layers, merge multiple GeoDataFrames, clip data to a region of interest (by extent or a masking polygon), and more. For example, one can quickly calculate the centroids of polygons or join a shapefile of regions with a table of statistical data by region ID.
Attribute creation: Add new attributes or columns to data based on expressions or functions applied to existing data (useful for deriving metrics or categories on the fly).
DataFrame/GeoDataFrame integration: The processing functions work directly with pandas DataFrames and GeoPandas GeoDataFrames, allowing users to blend cartograpy’s tools with the rich pandas data manipulation ecosystem.
Cartographic Mapping and Visualization: The mapper module enables fast creation of static maps for visualization of geospatial data. At the center is a powerful Map class that wraps Matplotlib and Cartopy functionality to simplify map generation. Key features include:
Layer addition: Easily add multiple layers to a map, such as choropleth polygons, point markers, line vectors (e.g., road or river networks), or raster tiles/images. The Map class handles coordinate reference systems and plot extents under the hood, so different data sources can be combined seamlessly.
Styling elements: Add common map decorations and annotations with one-liners. For instance, users can add a north arrow, scale bar, graticule (latitude/longitude grid lines), labels for features, titles and subtitles, and custom color palettes or shading. cartograpy includes a variety of preset color palettes (including those from Seaborn and Matplotlib) and allows custom palettes.
Legend management: Generate and place legends automatically, with several built-in style options (e.g., scientific, minimalist, academic styles) to suit different presentation needs. Legends can be customized or omitted as needed.
Figure sizing and export: Choose standard paper sizes (A4, A3, etc.) or custom dimensions for the figure. The package can automatically adjust the map’s extent and aspect to optimally fit the data (“smart centering”) so that the layout is well-balanced on the chosen canvas. Completed maps can be rendered to high-quality image formats like PNG and SVG for use in publications or reports.
Through these features, cartograpy drastically reduces the amount of code needed to produce a polished map. For example, a user can create a choropleth map of regional data with a title, north arrow, scale, and legend in just a few lines, whereas doing the same manually with Matplotlib and Cartopy would be considerably more involved. By automating many cartographic decisions (while still allowing manual overrides), cartograpy helps users focus on the analytical content of the map rather than low-level plotting details.
Implementation and Architecture
cartograpy is implemented in Python and is designed as a lightweight wrapper around robust existing libraries. The project is open-source (MIT licensed) and currently at version 1.1.0. Internally, the package is organized into four primary modules that correspond to the stages of geospatial work: cartograpy.data, cartograpy.processing, cartograpy.mapper, and cartograpy.styling. This modular architecture promotes clarity: for instance, data contains classes for acquiring external datasets, processing offers data manipulation functions, mapper contains the Map class and plotting functions, and styling provides helpers for customizing map appearance (fonts, colors, etc.). Under the hood, cartograpy leverages a range of established geospatial and scientific libraries. Key dependencies include GeoPandas (for data structures and file I/O), Shapely and PyProj (for geometric operations and coordinate reference systems), Rasterio (for raster data handling), OSMnx (for querying OpenStreetMap data), geopy (for geocoding services), and Cartopy (for cartographic projections and integration with Matplotlib). Visualization is built on Matplotlib (with the aid of Cartopy for map projections), and additional packages like Seaborn, pypalettes, and SciencePlots are used to enrich the styling options. By standing on the shoulders of these libraries, cartograpy can provide reliable performance and accuracy — for example, it relies on Cartopy’s projection engine to ensure that map layers are correctly projected and on GeoPandas for reading/writing a wide variety of GIS file formats. Each data acquisition class in cartograpy.data encapsulates a specific source or service (e.g., the GeoBoundaries class fetches boundary shapefiles from the geoBoundaries API, the OSM class uses OSMnx/Overpass API to retrieve OSM features, and WorldBank uses the World Bank’s REST API via the wbdata library). This design abstracts away the details of interacting with each service — the user calls a method like GeoBoundaries().countries("France", admin_level=1) and receives a GeoDataFrame of French regions, without needing to manually download or unzip any files. Similarly, processing functions in cartograpy.processing call underlying GeoPandas or Shapely functions, ensuring that heavy computations are done using optimized code. The cartograpy.mapper.Map class wraps Matplotlib’s Figure and Axes objects along with Cartopy’s GeoAxes, handling the creation of a map axis with a specified projection behind the scenes (WGS84 geographic coordinates are assumed by default for simplicity, but users can specify projections if needed). The architecture emphasizes extensibility and maintainability. Since cartograpy primarily glues together existing tools, it remains relatively thin: its role is to provide a smoother user interface rather than re-implement complex geospatial algorithms. This means the codebase is easier to maintain, and updates to underlying libraries (e.g., a new release of GeoPandas or Cartopy) can be incorporated by adjusting cartograpy’s wrappers if necessary. The modular approach also means users can use only what they need (for example, one could use just the data module to fetch data and then do custom analysis, or use the mapping module with their own preprocessed GeoDataFrame). This flexibility makes cartograpy applicable to a variety of workflows.

Use Cases
cartograpy’s unified approach lends itself to a variety of use cases across research and applied domains. A few representative scenarios include:
Socio-Economic Data Mapping: A researcher can quickly fetch country or regional boundaries and join them with statistical data (e.g., population or economic indicators) to create choropleth maps. For example, using the World Bank interface and geoBoundaries, one could retrieve the latest population data for all countries and visualize it on a world map with just a handful of commands, producing a ready-to-publish figure of global population distribution.
Urban Planning and Infrastructure Analysis: City planners or geospatial analysts can use cartograpy to obtain OpenStreetMap data such as road networks, public facility locations, or land use polygons for a city, then analyze and plot these on a map. For instance, one might download all hospital locations in a region and the road network via the OSM module, then use processing functions to filter and clip these data to the city boundary, and finally map them to assess coverage gaps. The process is streamlined compared to manually combining OSMnx (for data) and separate plotting code.
Environmental and Hydrological Studies: cartograpy can pull continent-scale hydrographic datasets (rivers, lakes) and help focus on a specific area. As an example, an environmental scientist studying water resources in West Africa could download the entire African river network (Hydro class), then use a polygon of the target country to clip the river network (processing.clip_gdf_by_mask) and visualize the result on an A4 map. The inclusion of automatic scaling, north arrow, and legend allows the scientist to produce a clear map of rivers in the study area with minimal effort.
Educational Use and Rapid Prototyping: For teaching GIS or for quick exploratory data analysis, cartograpy allows students and analysts to perform common geospatial tasks without extensive setup. A class assignment might involve geocoding a list of addresses and mapping them—using cartograpy, students can geocode addresses via the Geocoder and plot them on a base map in a straightforward script, focusing on interpretation rather than coding boilerplate. Similarly, data journalists or analysts can prototype maps within a Jupyter notebook interactively, retrieving data and updating map styles on the fly to tell a story with spatial data.
These use cases demonstrate cartograpy’s value in reducing friction in the geospatial workflow. By consolidating capabilities, the package enables quicker iteration and helps ensure that the technical overhead does not impede insights. Each scenario that would typically involve multiple disparate steps or software can be achieved within the cartograpy framework, highlighting its unique contribution to the geospatial toolkit.
